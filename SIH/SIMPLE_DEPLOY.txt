============================================================
DISASTERGUARD - SIMPLE DEPLOY GUIDE (NO GITHUB NEEDED)
============================================================

WHAT YOU WILL DO (in simple words):
- Backend (Node.js + SQLite) -> Fly.io  (FREE, supports SQLite)
- Frontend (HTML files)     -> Netlify (FREE, drag-and-drop)
- Database                   -> SQLite file on Fly.io (NO Neon needed!)
- GitHub                     -> NOT needed
- Cost                       -> $0

WHY NO NEON?
- Your backend uses SQLite (a file database), not Postgres.
- Fly.io gives a free persistent disk where SQLite file lives.
- So you do NOT need any external database.
- Using Neon would require rewriting the backend code (NOT allowed).

TOTAL TIME: 15-20 minutes
TOTAL COST: $0


============================================================
STEP 1: DEPLOY BACKEND ON FLY.IO (10 min)
============================================================

1.1) Create free Fly.io account:
     - Go to: https://fly.io/app/sign-up
     - Sign up with email (no credit card needed)

1.2) Install Fly.io CLI tool (flyctl):
     - Mac/Linux terminal:   curl -L https://fly.io/install.sh | sh
     - Windows PowerShell:   iwr https://fly.io/install.ps1 -useb | iex
     - Or download from:     https://github.com/superfly/flyctl/releases
     - Restart terminal after install.

1.3) Login to Fly.io from terminal:
     fly auth login
     (opens browser, click sign in)

1.4) Go inside backend folder:
     cd SIH/backend
     (replace path with wherever you unzipped the project)

1.5) Launch the app:
     fly launch
     Answer the prompts:
       ? App name?              -> disasterguard-backend
       ? Choose region?         -> choose closest (e.g., bom, sin, fra, iad)
       ? Postgres database?     -> NO      (we use SQLite, not Postgres)
       ? Redis database?        -> NO
       ? Create volume (1GB)?  -> YES
       ? Deploy now?            -> YES
     Wait 2-3 minutes. Done.

1.6) Set environment variables (one by one):
     fly secrets set JWT_SECRET=$(openssl rand -hex 32)
     fly secrets set DB_PATH=data/disasterguard.db
     fly secrets set PORT=5000

1.7) Seed the database (creates login accounts):
     fly ssh console
     cd app
     node database/seed.js
     (should print: [Seed] Seeding completed successfully.)
     exit

1.8) Test backend is live - open in browser:
     https://disasterguard-backend.fly.dev/api/health
     Should show: {"status":"healthy","seededUsers":8}

     If you see "healthy" and seededUsers=8, backend is DONE.
     Write down your backend URL:
     https://disasterguard-backend.fly.dev


============================================================
STEP 2: EDIT ONE LINE IN api.js (1 min)
============================================================

2.1) Open file: SIH/api.js (use Notepad / VSCode / any editor)

2.2) Find line 12 (it says):
     const API_BASE = 'http://localhost:5000';

2.3) Replace it with:
     const API_BASE = 'https://disasterguard-backend.fly.dev';
     (use YOUR backend URL from step 1.8)

2.4) Save the file.


============================================================
STEP 3: DEPLOY FRONTEND ON NETLIFY (3 min, drag-drop)
============================================================

3.1) Open browser, go to:
     https://app.netlify.com/drop

3.2) Sign up if needed (free, email login).

3.3) You will see a big dashed box "Drag and drop your site
     folder here".

3.4) Drag your ENTIRE SIH folder onto the box.
     (the folder that contains login.html, api.js, backend/, etc.)

3.5) Wait 30 seconds. Done!

3.6) Netlify gives you a URL like:
     https://disasterguard-1234.netlify.app
     (or similar - random name, you can rename it later)

3.7) Test frontend is live - open:
     https://YOUR-NETLIFY-URL.netlify.app/login.html
     Should show the DisasterGuard login page.

============================================================
TROUBLESHOOTING (if something fails)
============================================================

Q: Backend health shows seededUsers=0
A: SSH in and re-seed:
   fly ssh console
   cd app
   node database/seed.js
   exit

Q: Login fails with 401 error
A: Same as above - database not seeded.

Q: "Failed to fetch" error in browser console
A: Check api.js line 12 - URL must match your Fly.io backend URL exactly.
   Must start with https:// and end with .fly.dev (no trailing slash).

Q: Real-time Socket.IO not working
A: Some firewalls block WebSockets. Try mobile data.
   Socket.IO will auto-fallback to polling (slower but works).

Q: Frontend loads but no data appears
A: Backend may be sleeping. First request takes ~30 sec on free tier.
   Just refresh the page after waiting 30 seconds.

Q: Fly.io asks for credit card
A: Skip the credit card step. Free hobby plan does NOT need it.
   If they insist, use a virtual card or try Render.com instead
   (Render requires GitHub though).


============================================================
ALTERNATIVE: USE RENDER IF FLY.IO DOESN'T WORK
============================================================

If Fly.io fails for any reason, you can use Render instead:
- Render requires GitHub (so this is the alternative path)
- Push your SIH/ folder to a new GitHub repo
- Render: create new Web Service, Root=backend, Start=npm start
- Add 1GB persistent disk mounted at /opt/render/project/src/data
- Frontend: same Netlify drag-drop as above

But try Fly.io first - it's the no-GitHub path you asked for.
